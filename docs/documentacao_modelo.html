Painel de faltas em consultas

Modelo semântico e relatório do projeto de previsão de faltas: 110 mil consultas da rede pública de Vitória (ES), o risco previsto por um modelo de Machine Learning e a ação recomendada para cada consulta.

Esta documentação foi gerada por um script que lê os arquivos do projeto Power BI (formato .pbip, TMDL). A estrutura, os tipos e as fórmulas DAX vêm direto do modelo; as descrições de negócio foram escritas à parte.

Arquitetura

Os dados são preparados em Python (notebooks do projeto) e chegam ao Power BI como arquivos CSV no padrão brasileiro. O Power Query só lê e tipa as colunas: toda a lógica pesada fica nos notebooks.

Modelo de dados

Cultura do modelo: pt-BR. Uma relação liga a agenda da semana de teste ao histórico, para que os filtros de faixa etária e bairro também filtrem a agenda. As tabelas de premissas e modelos são de apoio e não se relacionam com as outras.

  • Agenda.consulta_id (muitos) → Consultas.consulta_id (um), filtro em direção única

Decisões de modelagem

  • Lógica no Python, não no Power Query. Limpeza, variáveis, modelo e regra de custo são feitos nos notebooks, que já têm testes e conclusões. O Power BI só apresenta, o que deixa o modelo leve e fácil de revisar.
  • Colunas de exibição separadas das técnicas. Rótulos como "Ação recomendada" e "Histórico do paciente" são cópias ordenadas por colunas ocultas, porque uma coluna não pode ser ordenada por outra derivada dela mesma (dependência circular).
  • Tipos convertidos com cultura pt-BR. Os CSVs usam vírgula decimal; tipar com "pt-BR" evita números lidos como texto ou multiplicados por mil.
  • Filtro de volume no ranking de bairros. O gráfico só mostra bairros com 500 consultas ou mais, para não destacar taxas instáveis de bairros pequenos.
  • Tema e ícones próprios. O relatório usa um tema JSON registrado no projeto e ícones SVG desenhados para o painel.

Pontos de atenção

  • Caminho fixo dos arquivos. As consultas apontam para D:\Projetos IA\Projeto 2 Saude\powerbi\. Para rodar em outra máquina, troque por um parâmetro do Power Query com a pasta dos CSVs.
  • Tabela Modelos digitada. As métricas foram copiadas dos notebooks 03 e 04. Se os modelos forem retreinados, atualize os valores ou passe a ler um CSV.
  • Premissas ilustrativas. Custos e efeitos das ações não foram medidos; a economia exibida depende deles e deve ser validada com um teste A/B.
  • Visuais ocultos de uma versão anterior. O projeto guarda 14 visuais vazios e ocultos da primeira versão do layout. Não afetam o relatório e podem ser apagados no painel Seleção.

Como atualizar

  1. Rode os notebooks do projeto no Colab, do 00 ao 06. O 06 gera os CSVs em dados/powerbi no Google Drive.
  2. Baixe a pasta powerbi para o caminho usado pelo modelo (ou ajuste o parâmetro de pasta).
  3. Abra o Painel Faltas Consultas.pbip e clique em Atualizar.
  4. Confira os indicadores da seção Validação e publique de novo.
